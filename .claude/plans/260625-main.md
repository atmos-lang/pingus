# Plan: Main / Screen Orchestration

`main.atm` is the application entry point: it sets up the
window, then loops dispatching the menu's chosen `:Id` to the
matching screen (Continuation Passing).

Until the real screens are ported, each non-exit id opens a
placeholder `Blank` screen.

## Blank screen

`Blank (text)` shows `text` centered and terminates when
`Escape` is pressed.

```
val task Blank (text) {
    watching :key.dn [key='Escape'] {
        loop on :draw {
            pico.set.pencil [ color="white" ]
            pico.output.draw.text(text, ['%', x=0.5, y=0.5, h=0.1])
        }
    }
}
```

The env clears each frame, so `Blank` draws on a black screen
(the menu has already terminated when its id is returned).

## CPS dispatch

The menu returns the clicked `:Id`; `main` decides the next
screen and, on return, loops back to the menu.

```
loop {
    val id = await Menu()
    match id {
        :Story     => await Blank("Story")
        :Editor    => await Blank("Editor")
        :Levelsets => await Blank("Levelsets")
        :Options   => await Blank("Options")
        :Exit      => break()
    }
}
pico.quit()
```

### Screen mapping (target, from C++ `on_click` / Céu `escape`)

| id          | next screen                         | back to menu |
|-------------|-------------------------------------|--------------|
| `:Story`    | worldmap (`tutorial.worldmap`)      | yes          |
| `:Editor`   | editor (stops music)                | yes          |
| `:Levelsets`| level menu                          | yes          |
| `:Options`  | options (pauses the menu)           | yes          |
| `:Exit`     | quit                                | terminates   |

## Original screen model (reference)

`ScreenManager` keeps a **stack** (`screens` vector);
`get_current_screen()` is the top.
Each frame, only the **top** screen gets `update_input` /
`update` / `draw` — everything beneath is frozen.

- push: append + `on_startup()`; pop: remove + `on_startup()`
  on the newly exposed screen.
- so an underlying screen (e.g. the menu) is **paused**
  (state intact, not updated/drawn), then **resumed as the
  same instance** on pop — never restarted, never background.
- transition: `fade_over` — the new screen is revealed through
  a **centered rectangle growing 0 -> full** over the old
  screen, ~0.5 s. It is **draw-only**: no `update`/input during
  the fade, and input is flushed (`input_manager.refresh()`)
  at the end. The new screen becomes reactive only after.

## Transition model (port decision)

The stack is uniform, but keeping old state alive is only
*required* when "back" must resume **transient in-progress
state** (a running simulation). For menus/static screens the
state is cosmetic (menu cloud-scroll) or persisted elsewhere
(settings, progress in `StatManager`), so restart == resume.

Rule for the port:

- persist real state in a **model**, not in the screen object;
- **terminate + re-enter** screens by default (`await Screen()`)
  — this is the current CPS loop; the menu restart-on-return is
  fine (more honest than the original's incidental pause);
- **keep-alive + suspend** only to pause a live activity
  (in-game pause/overlay) — Atmos `toggle`/`watching`, the Céu
  `emit go_options` pattern (cf. pico-rocks `toggle battle`).

## Transition: Stack task

`fade_over` rebuilt with structured concurrency. A `Stack` task
drives one screen change with the centered box-expand reveal.

Sketch: `Stack (cur, nxt)`

1. receive `cur` (live xtask) and `nxt` (task to start).
2. `pico.layer.screenshot(nil, :snap)` (capture cur's frame);
   `toggle cur(false)` (freeze cur + its subtree).
3. draw `:snap` on **window** (full backdrop); animate
   `pico.set.scene [clip=box(p)]` on **world**, `p: 0 -> 1`
   (~0.5 s). env runs `expert(true)`, so window-draw is allowed.
4. `spawn`/`await nxt` (draws on world, clipped to the box).
5. on finish: reset the world clip, drop `:snap`.

Primitive map:

| step          | primitive                                   |
|---------------|---------------------------------------------|
| pause cur     | `toggle cur(false)` / resume `toggle (true)`|
| snapshot      | `pico.layer.screenshot`                     |
| backdrop      | draw `:snap` on `window` (expert)           |
| reveal        | `pico.set.scene [clip=...]` on `world`      |
| start next    | `spawn` / `await nxt`                        |

Consequence — `Stack` implies the **keep-alive** model:
`cur` must be a **live task that signals its choice** (e.g.
`emit`/`pub`), not one that terminates (current `await Menu()`).
With `await`-to-id there is nothing to resume; "back" re-spawns
fresh. With `toggle`, `cur` stays paused underneath and "back" =
`toggle cur(true)` + reverse reveal.

Open questions:

- pause vs terminate `cur` behind the transition (parameterize?
  pause for resumable screens, terminate for throwaway). The
  screenshot is the backdrop either way.
- how a live screen reports its choice without terminating
  (`emit :goto, nxt` to `Stack`, or a `pub`).
- de-risk first: prototype the pure reveal (screenshot world ->
  draw on window -> animate `scene.clip` while a 2nd task draws
  world) before building `Stack`.
