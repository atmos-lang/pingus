# Plan: Main / Screen Orchestration

`main.atm` sets up the window and hosts the menu (`await Menu()`),
plus the `Blank` placeholder screen and the `Fade` transition.
The menu (`menu.atm`) is the persistent base of the screen stack:
it owns the dispatch loop and opens a screen (via `Fade`) for each
non-exit button.

## Current model (menu-owned dispatch)

The menu does not return an id.
The 5 buttons are spawned once; a click signals `emit @2 :Button
[id]`. The loop: `val but = await :Button`,
`match but@1 -> await Fade(menu, Next, text)`; `:Exit` ends the
loop (and the program).

`Fade(cur, Next, ...)` freezes `cur` (snapshot + `toggle` off),
grows `Next` over the snapshot, runs it, then shrinks `Next` back
to the resumed `cur` on `Escape` (see `260625-fade.md`).
`Blank (text)` is the placeholder `Next`: centered text on an
opaque bg until `Escape`.

## Screen mapping (from C++ `on_click` / Céu `escape`)

| id          | next screen                    | back to menu |
|-------------|--------------------------------|--------------|
| `:Story`    | worldmap (`tutorial.worldmap`) | yes          |
| `:Editor`   | editor (stops music)           | yes          |
| `:Levelsets`| level menu                     | yes          |
| `:Options`  | options (pauses the menu)      | yes          |
| `:Exit`     | quit                           | terminates   |
